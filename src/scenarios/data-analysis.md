# 数据分析与洞察

> 场景定位：让业务人员用一句话查数据、出图表、写分析——不用会 SQL，不用排队等数据团队。

## 业务痛点

| 痛点 | 具体表现 |
|------|----------|
| 取数靠提需求 | 业务想看一个数，提需求给数据团队，排期 2 天起 |
| SQL 门槛高 | 业务人员不会写 SQL，简单的数也要找人 |
| 报表口径不一 | 不同人算同一个指标，结果对不上 |
| 分析停留在表面 | 有数据没洞察，"销售额降了"但说不出为什么 |
| 数据散在多处 | Excel、数据库、业务系统各存一份，汇总靠手工 |

## 解决方案

```mermaid
graph LR
    A["业务人员自然语言提问"] --> B["AI 理解意图"]
    B --> C["生成查询 / 处理数据"]
    C --> D["执行：数据库 / Excel / API"]
    D --> E["结果 + 图表 + 解读"]
    E --> F{"需要深入?"}
    F -->|"是"| A
    F -->|"否"| G["导出报告"]
```

**核心能力**：
- **自然语言查数**：对接 MySQL / PostgreSQL / ClickHouse 等数据库，一句话生成查询并执行
- **Excel 即席分析**：上传表格文件，直接提问，AI 用脚本完成清洗、透视、统计
- **可视化输出**：分析结果自动渲染为交互式图表（趋势、对比、占比、分布）
- **指标口径沉淀**：把指标定义写入知识库，保证全公司算的是同一个数

## 典型子场景

### 子场景 1：自然语言查数据库

| 提问 | AI 行为 |
|------|---------|
| "上个月华东区销售额是多少？" | 生成 SQL → 执行 → 返回数值 + 环比 |
| "近半年各产品线收入趋势" | 查询 → 输出折线图 + 趋势解读 |
| "哪些客户连续 3 个月没有下单？" | 多条件查询 → 输出名单表格 |

:::warning 数据安全
- 为 AI 配置**只读账号**，从权限上杜绝误操作
- 敏感表/字段通过视图或权限隔离，AI 只能访问授权范围
- 查询日志全量留痕，可审计
:::

### 子场景 2：Excel 即席分析

1. 上传销售明细 / 运营数据 Excel
2. 直接提问："按区域汇总 Q2 销售额，找出环比下滑最多的区域"
3. AI 用 Python 脚本完成清洗、聚合、统计
4. 输出结果表格 + 图表 + 结论，可导出处理后的文件

适合没有入库的临时数据、外部数据、一次性分析需求。

### 子场景 3：经营分析报告

- 组合多个数据源：数据库指标 + Excel 补充数据
- 按报告框架自动成稿：核心指标 → 趋势分析 → 异常归因 → 建议
- 结合定时任务，每周一早上自动推送上周经营简报（见[定时报告与监控播报](/scenarios/scheduled-reports)）

### 子场景 4：指标口径统一

- 把指标字典（定义、计算口径、数据来源）沉淀到知识库
- 任何人提问"活跃用户数"，AI 都按统一口径计算并标注口径说明
- 口径变更时更新知识库，全员同步生效

## 实施步骤

### 第 1 步：明确分析场景与数据源（1 天）

| 问题 | 示例答案 |
|------|----------|
| 谁在用？ | 销售运营、产品经理、管理层 |
| 高频问题有哪些？ | 销售额、用户数、转化率、库存 |
| 数据在哪？ | MySQL 业务库、每周导出的 Excel |
| 敏感数据范围？ | 薪酬表、客户手机号需隔离 |

### 第 2 步：准备数据访问（1-2 天）

- 数据库：创建只读账号，按需建分析视图隔离敏感字段
- 提供表结构说明（表名、字段含义、关联关系），上传到知识库
- Excel：整理常用模板与历史文件

:::tip 表结构说明很关键
AI 生成查询的准确率高度依赖对表结构的理解。一份清晰的"数据字典"文档（每张表是干什么的、关键字段含义、常见关联方式）能让准确率大幅提升。
:::

### 第 3 步：配置分析流程（半天）

1. 通过 MCP 工具或 API 连接数据库
2. 配置提示词：角色设定、口径规则、输出格式（表格/图表/解读）
3. 设定护栏：只读约束、行数限制、超时控制

### 第 4 步：验证与调优（3-5 天）

- 收集 30-50 个真实业务问题测试
- 对照数据团队的人工查询结果核对准确性
- 高频错误 → 补充数据字典或修正口径说明

### 第 5 步：推广与运营

| 渠道 | 方式 |
|------|------|
| Web 对话界面 | 业务人员直接提问 |
| 嵌入 BI/办公系统 | JS SDK 集成到现有门户 |
| 定时推送 | 周期性报表自动生成推送 |

## 效果参考

| 指标 | 实施前 | 实施后（参考值） |
|------|--------|-----------------|
| 常规取数时效 | 提需求等 1-2 天 | 一句话 < 1 分钟 |
| 数据团队临时取数工作量 | 占工时 40%+ | 减少 60-70% |
| 指标口径争议 | 频繁发生 | 统一口径 + 自动标注 |
| 周报数据准备 | 半天手工汇总 | 自动生成 |

:::warning 效果说明
以上为行业参考值。查询准确率取决于数据字典的完备程度；涉及经营决策的数据，重要结论建议人工复核。
:::

## 进阶玩法

| 进阶方向 | 说明 |
|----------|------|
| 归因分析 | "销售额为什么降了"→ AI 自动下钻维度找原因 |
| 异常检测 | 定时扫描核心指标，异常波动自动告警 |
| 多源联合 | 数据库 + Excel + API 数据联合分析 |
| 分析模板化 | 高频分析沉淀为技能，一键复用 |
| 对话式 BI | 追问式探索："那华南区呢？""按月份拆开看" |
